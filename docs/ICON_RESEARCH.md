# Icon Research: the monster iconography pass

Self-directed goals for this session, and the record of how the six Bellgrave
Diorama enemy icons were chosen. Written so a future session (or future me)
doesn't have to re-derive the method — reuse it via
`.claude/skills/waxlight-iconography`.

## Goal

The first icon-suite swap (session before this one) worked mechanically but
was chosen too fast — slugs were picked by guessing plausible names, not by
comparing real candidates. The ask this round: search **wide**, compare
candidates **as rendered in-game** (not raw black-on-white previews), and
only lock in a pick once it's demonstrably the best available fit.

## Method

1. **No API access to game-icons.net's own search** (its site domain and
   jsDelivr/GitHub-API mirrors are outside this session's egress allowlist —
   confirmed via `/root/.ccr/README.md`'s "403 = do not retry" rule). Worked
   around it by batch-probing `raw.githubusercontent.com/game-icons/icons/
   master/<author>/<slug>.svg` (that CDN host *is* reachable) across ~15
   author folders (`lorc`, `delapouite`, `sbed`, `skoll`, `cathelineau`, …)
   with curated slug guesses grouped by theme (ghost/spirit, skull/bone,
   bell, claw/hook, crypt/boss). Two probe waves, ~150 URLs total, ~50 hits.
2. Built a **real montage**: every hit rendered as an actual dark-disc,
   blood-ring medallion token — the same visual language the diorama uses —
   not the raw game-icons.net preview style. This matters: several icons
   that look fine on a white background (e.g. `bell-shield`) read as vague
   blobs once recolored and shrunk into a token; some that look busy at
   preview size (`ringing-bell`) read cleanly once simplified into the
   medallion.
3. Shortlisted per-creature finalists, re-rendered them larger side by side,
   and picked by direct comparison, not first-guess.

## Final picks (and why they beat the first pass)

| Enemy | First pass | New pick | Why the new one wins |
|---|---|---|---|
| Vowless Pilgrim Shade | `spectre` (a bat/gargoyle) | `cowled` | A hooded, cloaked, hands-clasped figure — reads as *pilgrim* instantly. The old pick read as a generic monster, not a pilgrim. |
| Ash-bitten Bones | `skull-crossed-bones` (generic poison-symbol read) | `skull-crack` | Visible fracture/damage on the skull sells "ash-bitten" (worn, broken) rather than a stock hazard icon. |
| Bell-Ringer Shade | `bell-shield` (an odd shield-shaped abstraction) | `ringing-bell` | A literal bell with sound-wave lines — the single clearest glyph for a creature named after a bell. |
| Bone-Hook Crawler | `hook` (a fishing hook — reads as a tool, not a creature) | `monster-grasp` | A reaching clawed hand — reads as a *crawling creature*, which is the actual point of the name. |
| Bone Rattle Add | `dread-skull` (duplicated the boss-adjacent skull silhouette) | `ribcage` | A distinct silhouette from the other two skull-family enemies, and "ribcage" is exactly what rattles. |
| Bellgrave Warden | `grim-reaper` (a plain hooded silhouette, under-reads at token size) | `crowned-skull` | Ties directly to the Warden's actual lore (a skull crowned by a cracked, wax-dripping bell) instead of a generic "death" glyph every fantasy game uses. |

## A bonus find: the player portrait didn't hold up at token size

While re-verifying the diorama with the new icons, the player's forged
portrait (`bulwark-default.png`) rendered as almost nothing — a tiny warm
dot in a black circle. Root-caused it properly before assuming it was a
render bug: isolated the `<image>` element in a standalone HTML page (no
React, no app CSS) and it reproduced identically, then compared the same
PNG at 56px / 120px / 220px in plain `<img>` tags. The portrait's
low-key/dark compositing (correct and painterly at Hero-panel size, ~220px)
simply collapses once downsampled to a ~40-56px combat token — the lit face
occupies a small fraction of a mostly-near-black square, and at that scale
the dark tones crush together with the token's own dark disc background.

Fix: `EncounterDiorama.tsx`'s `Token` now takes an `imageZoom` prop. The
player's `<image>` element is deliberately oversized (2.4×) and kept
centered on the same point before being clipped by the token's circle — the
standard "avatar crop" trick (same idea as `object-fit: cover` plus a
manual zoom). The Hero panel and channel-rail portrait plates are unaffected
(they have room to show the whole composition); only the tiny combat token
needed the crop.

## Left for later (not blocking, noted for the next pass)

- The skull-family enemies (Ash-bitten Bones, Bone Rattle Add, Bellgrave
  Warden) all still read as "a skull" at a glance from across the room —
  distinct enough up close (crack vs ribcage vs crown) but a future pass
  could look for more silhouette variety per docs/GRAND_VISION.md §1's
  long-term goal of bespoke per-creature icons.
- The Bone-Hook Crawler's chosen icon (`monster-grasp`) is a hand/claw, not
  literally a hook — it read better than any actual "hook" glyph found, but
  a custom-drawn hook-limbed silhouette (in the Waxlight medallion style)
  remains the more precise long-term fit if bespoke icon art is ever revisited.
