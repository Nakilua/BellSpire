# BellSpire UI/UX Direction

BellSpire should feel like a gothic MMO client for a solo-local living world, not a dashboard, landing page, or generic chat app.

## UI Law

- The first impression should feel like entering a local MMO realm.
- `/login` is character select and character creation, not a marketing hero.
- The main screen is a game client: channel rail, party/social memory, narrative feed, map, quest tracker, inventory, character state, and command hotbar.
- Visual assets are mood-setting scene art only. They cannot create canon, locations, NPCs, loot, classes, or story facts.
- Maps should use BellSpire-native hand-drawn plates wherever possible, with interactive pins layered on top.
- Shops, trainers, guild boards, crafting stations, shrines, vendors, route services, and later profession/service markers should be shown as source-governed UI pins or legends, not baked into tiny unreadable map text.
- The center feed must stay readable because BellSpire is text/story-first.
- Combat state must be obvious: HP, Oath, lane, enemy intent, and available actions.
- Loot must show rarity and source status clearly.
- Mobile must remain usable even if the desktop view is the primary target.

## Visual Direction

- Gothic cathedral MMO.
- Painted scene backdrops.
- Ink, wax, bronze, red glass, bone parchment, black stone, and shrine light.
- Motion should feel like doors opening, bells answering, and UI plates locking into place.
- Avoid generic SaaS cards, big marketing sections, empty purple gradients, and decorative clutter.

## Source Safety

The UI may make BellSpire feel richer, but it must not pretend unfinished systems are complete.

- Simulated social play is local.
- API Director replies are narration/social texture, not core state ownership.
- Permanent gear still follows source law.
- New images, icons, or UI labels must respect the compendium and workbooks.
